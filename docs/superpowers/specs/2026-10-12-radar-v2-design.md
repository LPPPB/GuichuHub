# GuichuHub 排行榜雷达图 v2 维度设计

日期：2026-10-12。状态：用户已于本聊天确认启动本方案；实施计划准备中，尚未实现或部署。

## 目标与边界

用户要求重新设计排行榜雷达维度，解决现有实时关注缺失、图形相似、维度和基准不合理的问题。

本方案将雷达定义为“视频表现画像”：让用户看清累计传播规模、不同互动行为和近期真实增长。分数表示相对于站内观测样本的表现，不表示内容质量、爆火概率或 B 站全区排名。首版只改变雷达口径及其数据组装，不改变排行榜排序和潜力评分。

成功标准是含义清楚、计算可解释、数据来源可追溯、头部差异不被固定门槛抹去。同样表现的视频允许有相似形状，不以制造形状差异为优化目标。

## 已核对的数据条件

- 当前仓库的 video_observations 已存储时间、播放、点赞、投币、收藏、分享、评论、弹幕及原始在线人数，支持真实增量计算。
- 2026-10-12 的公开观测接口中，《烧心大赛》有 37 个观测点，《选秀，但是剧组很穷》有 52 个观测点；两条最新观测均为北京时间 12:30。
- 《烧心大赛》该观测的播放为 5,117,624，在线人数为 242；过去 6 小时增加 16,526 播放，即约 2,754.3 播放/小时。
- 《选秀，但是剧组很穷》该观测的播放为 731,938，在线人数为 298；过去 6 小时增加 89,645 播放，即约 14,940.8 播放/小时。
- 这说明排行榜缓存没有利用的较新观测已经存在。实施时应先接入现有观测，测量全榜覆盖；根据实际缺口补采集，不能直接假设所有头部都需要新增采集任务。
- 上述两条只用于验证数据可行性，不能作为评分基线，也不能证明全榜已有充足历史。

## 选定方案：六轴行为画像，在线状态单独展示

顺时针固定排列如下。

| 维度 | 用户要回答的问题 | 原始指标 | 评分口径 |
|---|---|---|---|
| 播放规模 | 已经获得多大累计传播？ | 最新有效累计播放数 | 全部参考样本的播放分位位置 |
| 观众认可 | 观众是否用点赞、投币表达支持？ | 每千播放点赞数、每千播放投币数 | 两项各自的同龄样本分位分，等权平均 |
| 收藏倾向 | 观众是否愿意留存这个视频？ | 每千播放收藏数 | 同龄样本分位分 |
| 讨论活跃 | 观众是否愿意评论、发弹幕？ | 每千播放评论数、每千播放弹幕数 | 两项各自的同龄样本分位分，等权平均 |
| 分享倾向 | 观众是否愿意分享这个视频？ | 每千播放分享数 | 同龄样本分位分 |
| 近期增速 | 最近观测窗口内播放增长多快？ | 近期实际播放增量 / 实际间隔小时 | 同龄样本的播放增速分位分 |

点赞、投币、收藏、评论、弹幕、分享各自只进入一个互动轴。播放规模和近期增速分别描述累计量和近期流量，允许相关，但不混合计算。名称使用“认可”“倾向”“活跃”，不将这些行为直接宣称为内容质量、二创价值或情绪好坏。

观众认可与讨论活跃的两项等权，是首版透明的设计取舍，不是经过验证的行为价值权重。它们先分别转换成分位分，再平均，不把不同量级的原始计数直接相加。复合轴是两个相对位置的平均分，不能把复合轴 90 分解释为整体超过 90% 的视频；提示中注明“综合相对分”。后续如要改权重，必须用回放证据评审并升级算法版本。

收藏不能证明重复观看；分享不能证明推荐算法扩散；评论与弹幕不区分正负情绪。弹幕还可能受视频时长影响。首版保留各子指标和视频时长用于解释与分布审查，不引入缺乏数据验证的时长惩罚系数。

## 统一的原始数据规则

1. 每个视频的累计维度使用同一条最新、字段完整且有效的真实观测。雷达旁标明该观测时间。不要拼接不同时间的互动数与播放分母，也不要将 API 缺字段默认为 0。
2. 比率一律为 count / views × 1,000，单位为“次/千播放”，不是唯一观众参与概率。同一观众可以重复播放、投币、评论或发弹幕，指标可超过 1,000。
3. 播放为 0 时，播放规模可以为 0；互动比率不可计算。字段缺失、估算数据、无效计数或过期数据均不能成为真实 0。
4. 首版播放不足 1,500 的视频，保留播放规模和原始指标，互动轴标为“样本较少”，不给确定分位分。1,500 是首版建议门槛，需在回放中检查，不是统计显著性的保证。
5. 累计观测超过 24 小时标为过期；近期增速末点超过 90 分钟标为过期。这是按当前小时级观测设计的初始有效期，实施时须核对真实任务周期并写入版本配置。
6. 若现有存储无法辨认真实值与估算值，应先补足来源标记，再发布 v2，不能把缺少来源信息当成已验证实测。

## 近期增速的精确定义

末点 t1 是最新有效播放观测。目标起点为 t1 - 6 小时；在实际间隔 5～7 小时的有效观测中选择最接近目标的一点 t0，同距时选择更早的点。

speed = (views(t1) - views(t0)) / ((t1 - t0) / 3600)

- 展示实际窗口，例如“最近 6 小时 +89,645，约 14,941 播放/小时”；非 6 小时窗口必须注明实际时长。
- 没有合格起点时显示“观测不足”，不退回累计播放 / 发布时长，不混用 24 小时增速。
- 播放无增长时，增速为真实 0；播放计数下降时标为“计数异常”，不强行裁成 0。
- 只描述增长速度，不宣称“正在加速”。加速需要比较两个可比窗口，首版不加入此含义。

## 基准设计

参考样本来自过去 30 天内采集到的全部鬼畜分区视频，而非当前排行榜、当前页或潜力候选池；含已火视频。每个 bvid 在一个基线版本中只贡献一条最新有效观测，避免高频观测的视频获得更大权重。构建基线时的截止时间和来源必须可追溯。

播放规模使用全部有效参考视频。互动和增速使用同龄参考组，按观测时距发布时间分为：0～1 天、1～3 天、3～7 天、7～14 天、14～30 天、30 天以上。前闭后开，最后一组包括 30 天。页面解释“播放规模对比全部观测样本，其余轴对比同龄视频”，避免将不同参考组的原始值直接比较。

每个指标有效参考样本至少 200 条。组内不足时，在固定基线构建阶段合并相邻年龄组：先合并年龄区间最近的一组，同距优先更年轻的组；合并后仍不足则继续，直至满足或覆盖全部年龄。合并结果固定并记录，前端显示实际参考年龄范围。仍不足时显示“参考样本不足”，不退回当前页排名或旧版固定满分线。200 是首版基线质量门槛，需要审查实际可用样本量。

首版使用经验分位位置：

score(x) = 100 × (参考值严格小于 x 的数量 + 0.5 × 等于 x 的数量) / 有效参考样本量

- 原始值为真实 0 时得分固定为 0，避免零互动因大量并列被画成中等表现。
- 保留一位小数；同值必须同分。不对相同表现人为拉开。
- 明显超过全部参考值时可以达到 100。分位数也不能保证头部永不饱和；需要回放检查参考样本是否覆盖热门视频，不能承诺换公式后每条图形都不同。
- 当前页排序、翻页、筛选不重新计算参考分布。
- 每周一北京时间 00:00 生成新基线并固化一个版本，使用截止此前 30 天的数据；周内冻结。新数据可更新视频指标，但基线版本不变。
- 首次启用时，旧记录的来源若无法证明则不纳入正式基线。积累足够的可信观测后，以首次构建时刻为截止生成启动基线，冻结到下一个周一 00:00；此前显示“参考样本不足”。这是解决首次启用冷启动的明确例外，不把新采集的数据倒填进已经截止的历史基线。
- 跨基线版本比较必须标明版本变化；历史雷达保留当时基线，不能悄悄用新基线重写旧分数。
- 有效但缺乏区分度的参考分布标为“基准无区分度”，不强行输出有含义的高低分。

## 在线状态与数据新鲜度

将“实时关注”从雷达移出，复用视频卡片现有“X 人正在看 / 最近观测 X 人”的展示位置，统一其数据来源、时间和状态，不新增第二处在线人数。这里的“在看观测”是同一指标的文案调整，不是一个新指标。读取最近一次有效原始在线观测，不展示平滑人数为此刻人数，不用 online_circuit_skipped 一项标记决定所有可用性。

现有 VideoCard 对本轮有在线采集的情况显示“X 人正在看”；本轮实测为空或被标记跳过时显示“最近观测 X 人”。优先使用 online_display，否则使用 online_count；后者可能是跨轮平滑值。当前文案切换没有按观测时间判定新鲜度，因此“正在看”不能保证是用户此刻打开页面的人数。

- 示例：“在看观测 242 · 12:30”。
- 超过 90 分钟：“历史在看 242 · 12:30”；数据过期状态明确保留。
- 从未有观测：“在看暂缺”。
- B 站返回 1,000+、1.1万等近似数时如实展示原始精度，不伪装成精确人数。
- 原始人数 0、1、2 等按观测值展示，不因低于 5 而改写为“无人观看”。
- 页面使用“观测”，不承诺持续实时刷新。各视频可用性先按实际观测时间、来源和精度判断，再用采集原因解释。

## 展示与交互

- 保留六边形、现有桌面/手机布局和进入视口展开动画；轴标签依次为播放规模、观众认可、收藏倾向、讨论活跃、分享倾向、近期增速。
- 同一张图六轴同为 0～100 相对表现分；单指标轴使用分位分，复合轴使用子指标分位分的平均分。网格标出 25、50、75、100，并简短说明“相对站内观测样本”。雷达面积不作为总评分。
- 鼠标悬停或手机点按轴端，显示原始指标、分位分、数据时间、参考年龄范围、基线版本。复合轴显示两项子指标及各自分位分。
- 缺失或过期轴标灰并解释原因；数据线在该轴断开，不连接成完整填充图。真实 0 在中心绘制实点，与缺失区分。
- 原始播放、互动计数、发布日期仍可直接查看。在线状态与雷达数据分别注明时间。

## 可选方案及取舍

1. 选定：上述六轴画像，在线人数独立。最能利用现有字段，同时解决重复计数和不稳定在线轴的问题。
2. 保留旧六轴，只提高满分线。改动较小，但互动与讨论、传播的重叠，以及“增长”依赖年龄的问题仍然存在，不采用。
3. 将六个原始互动行为分别做轴。解释最直接，但雷达缺少传播规模和近期增长，仍需另做时间表现图。本次排行榜场景不采用。

## 实施边界与验证要求

实施将涉及雷达计算、基线构建和持久化、最新观测批量读取、排行榜 payload 组装，以及雷达解释和在线状态展示。基线应由 Worker 构建并存储为版本化结果；API 批量读取，不能在每次页面请求时全库扫描或为每张卡片独立查询。现有雷达返回契约需要升级，旧数据与新算法必须可辨认。

实现前须确认真实生产任务周期、全榜观测覆盖、可辨认的指标来源、每个参考组的有效样本量，以及基线持久化位置。现有模型已存储原始指标，但这些条件尚未在全库验证。

启动核对补充：当前仓库调度为整点/半点轻量观测，观测目标已经强制包含榜单；当前 video_observations 没有指标实测来源字段，页面响应缓存只按抓取数据版本更新。实施计划因此包含新增来源元数据、观测更新触发的缓存失效，以及持久化的基线版本；只在隔离测试库验证新增迁移，不对生产或用户现有运行库执行迁移。

最低验证：

- 用真实全榜及广泛观测样本回放，报告各轴样本量、并列/封顶比例、缺失比例和子指标相关性；不能仅用榜单前 20 条调参。
- 相同视频、原始数据和基线版本，在排序/翻页/筛选后得分不变。
- 单独改变收藏数，只改变收藏倾向；改变分享数，只改变分享倾向；改变评论或弹幕只改变讨论活跃。
- 播放超 100 万不会自动封顶；认可分不复用旧互动质量分；近期增速不复用 trend_score。
- 短窗口、缺历史、计数下降、估算、字段缺失、真实 0、低播放样本、失效基线和过期观测均有明确不同状态。
- 页面同时验证桌面、手机点按、缺失轴和减少动态效果偏好；核对 API 读取量，避免逐卡查询。
- 回放只能证明数据和口径合理性，不能证明互动行为等价于内容好坏，也不能证明分位分具有未来预测能力。
