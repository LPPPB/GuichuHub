# GuichuHub：真实栏目网址与公开数据 HTML

日期：2026-10-18。状态：设计待审阅，产品代码尚未实施。

## 目标与范围

实施已讨论方案的第 1、2 项：九个公开栏目使用真实链接；公开持久化数据变化后，自动生成包含正文的初始 HTML。保留现有布局、图表、移动抽屉、账户及收藏交互。普通访客与搜索引擎获取相同 HTML，不按 User-Agent 分流。

本次不改采集规则，不合并或启用 PR #22，不调整生产数据，不部署。完整 SEO 文案优化、sitemap 扩展、IndexNow 属于后续第 3、4 项。本阶段仅补齐路由必需的自指 canonical、准确页面标题和主标题，防止新页面全部规范化到首页。隐私隔离是本阶段的数据契约要求。

## 方案选择

1. 只加客户端路由：改动小，但初始 HTML 仍缺数据，不能满足第 2 项。
2. 每个访问请求运行 React 服务端渲染：正文完整，但增加请求链依赖与实时渲染成本。
3. **采用独立公开页面生成服务**：Node 在内部定期读取成功发布的公开数据，复用 React 页面生成并缓存 HTML；Nginx 将九个精确页面路径交给该服务，静态资源继续由 Nginx 提供。

方案 3 使采集 Worker 保持 Python，不把页面生成故障传递给采集任务。只在数据实际变化时渲染，每次普通访问直接读取已生成文档。服务不直接连接数据库，不挂载私密数据或凭据。

## 1. 路由与导航

| tab ID | 唯一公开网址 |
| --- | --- |
| dashboard | `/` |
| kichu-rank | `/rankings/kichu` |
| memes | `/memes` |
| videos | `/rankings/potential` |
| meme-materials | `/meme-materials` |
| songs | `/bgm` |
| materials | `/materials` |
| danmaku | `/insights/discussion` |
| up-trends | `/up-trends` |

建立单一路由表，由 SSR、浏览器、导航和 Nginx 路径验证共同使用或校验，避免名称漂移。公开子页以无尾斜杠网址为准；尾斜杠版本永久跳转到规范路径。查询参数不生成额外快照或不同 canonical。

桌面侧栏、移动抽屉、页脚、首页栏目入口和品牌回首页入口使用 `<a href>`，保留现有类名、图标、展开状态与可访问标签。分组展开、收藏、主题和登录继续使用按钮。

普通左键可被浏览器路由拦截，以保持现有切页体验；Ctrl/Cmd/Shift 点击、中键、另存链接及新窗口遵守原生链接行为。同步 `pushState`、`popstate` 与 activeTab；直接访问和刷新初始化相应栏目，不能跳回仪表盘。

未知页面返回真实 404，不能回落到首页 200。开发控制台不变成公开页面：保持登录后的本地交互，不进入路由表、HTML 缓存或 sitemap。注销、登录后的跳转也通过统一导航接口处理。

## 2. 公开数据契约

API 增加仅供内部页面生成服务读取的只读路径 `/internal/public-pages`。Caddy 和 Nginx 的公网路径明确拒绝该前缀；服务通过 core 网络访问 API。即使误访问，该响应也仅包含允许公开的信息，不以网络隔离代替字段过滤。

响应按栏目提供 `status`、`content_version`、`source_updated_at`（可为空）以及强类型公开字段。数据只来自持久化看板、公开的 UP 分析读层及现有公开衍生数据；不触发采集、分析、名单配置或数据库写入，不使用手动抓取 LIVE 缓存，不依赖请求 Cookie、用户身份或客户端自选名单。

字段实行逐层允许列表，不能直接序列化整个 dashboard、analysis 或数据库记录：

- 视频：bvid、标题、公开作者、封面、公开指标及已有评分解释；链接根据合法 bvid 构造。
- 热梗、素材、BGM：现有公开名称、摘要、热度和关联公开视频。
- 弹幕评论：现有公开页面的文本、公开指标和来源作品；不导出原始采集包、会话或内部标识。
- UP 主动态：已公开追踪的作者摘要、公开投稿和聚合指标；不含申请理由、申请者、审核记录、任务信息、管理名单字段或非公开请求。

为标题、数量、嵌套层数和字节数设置边界；URL 只允许已校验的公开链接，不使用条目提供的地址发起请求。文本由 React 转义；内嵌 JSON 转义 `<`、脚本结束符及 U+2028/U+2029，覆盖脚本注入测试。

`content_version` 来自允许公开内容的稳定摘要，排除轮询时间与运行状态。无变化时不重渲染、不刷新内容日期。已有可靠来源时间才输出“数据更新于”；无分板块时间则展示“公开内容确认于”，使用首次观察该版本的时间并持久保留，不把全局采集时间当作新鲜度保证。

明确区分成功非空、成功且确认为空、暂不可用。只有数据源能证明是有效空结果时才发布空态；当前旧采集器的含混空数组不能覆盖已有成功列表。一个来源出错不清除其他来源已成功发布的页面。

## 3. HTML 生成、缓存与服务

在 frontend 镜像构建中增加独立的 Node 服务构建目标，生成生产 SSR bundle；运行时不启动 Vite 开发服务器。Nginx 和生成服务使用同一提交、同一构建资产清单，启动检查版本标识，避免旧 HTML 引用新版本不存在的 JS/CSS。

生成服务每 60 秒检查一次内部公开数据，单次请求超时 10 秒，同一时刻只运行一个生成周期；失败保留缓存，下一个周期重试。UP 数据按独立版本刷新，不依赖 dashboard 版本。只渲染发生变化的页面及确实引用了该变化的首页摘要。

每页使用同一次公开数据读取结果生成正文和内嵌启动数据，避免两者不一致。将完整文档、版本、准确时间写入新临时文件，校验成功后在同一文件系统原子替换。所有涉及同一批内容的候选页面渲染完成后，再切换该批次的可见缓存；不能让请求读到半个文件。

服务使用新建、专用的 `public_pages_cache` 卷保存成功页面；只写自己的目录，不挂载生产数据库、私密目录、日志或现有业务卷。缓存按构建版本分区；新版本不能直接提供引用旧资产的缓存，先在内存读取兼容公开数据并用当前 bundle 重建。保留上一版缓存，不自动清理历史业务文件。

启动时先读取兼容缓存，再检查最新公开数据。若没有成功页面且数据源不可用，返回明确的 503、`Retry-After` 与 `X-Robots-Tag: noindex`，不返回伪装成完整页面的 200 加载框架。其他已有成功页面照常可访问。

Nginx 仅代理九个精确页面路径；哈希静态资源、favicon、robots 与现有 sitemap 继续按现有策略提供。HTML 返回 UTF-8、`Cache-Control: no-cache` 和基于文档的 ETag；支持 GET/HEAD 与条件请求，未知路径 404，不缓存账户响应。内部导出路径在公网返回 404。

## 4. React 启动与正文

`App` 接收 `initialTab`、`initialData` 和经过筛选的辅助数据。服务端渲染复用现有组件，首次就输出排名、作品名、作者、素材、热词等真实文本。图表在无浏览器环境显示同一公开数据生成的简洁列表或统计摘要，JS 启动后增强交互。

客户端从内嵌启动数据恢复同一树并使用 `hydrateRoot`。主题、收藏、身份、屏幕尺寸及本地弹幕屏蔽在 hydration 后生效；它们不能影响 SSR 首次树。客户端后续公开请求失败时继续展示快照，刷新请求不得将现有正文先清空为加载状态。

UP 主动态的 lazy 组件须在 SSR 完成后再发布 HTML，不能把 Suspense loading 当成成功正文。为该组件增加公开初始分析参数，保证无 JS 时能看到公开作者和作品摘要。

浏览器保持现有手动 LIVE 浏览能力，但 LIVE 不能写回生成缓存。收藏与登录等个人内容只在客户端授权请求后出现。页面不能通过 CSS 隐藏另一套专供爬虫的正文。

每页具备对应栏目标题及自指 canonical；主标题与该页正文一致。现有 favicon 不变。完整 description、结构化数据、sitemap 多页发现与 IndexNow 留到后续阶段；当前 sitemap 仍可保留首页，真实导航已提供新页发现入口。

## 5. 实施次序与验证

1. 先为路由映射、直接打开、原生链接行为、前进后退及未知路径写失败测试，再实现导航。
2. 为只读导出编写字段允许列表、跨用户一致性、不使用 LIVE、失败/有效空态和独立 UP 版本测试，再实现适配器。
3. 为真实正文、启动数据一致、恶意文本、无变化不重建、故障保留、重启恢复及构建版本不匹配编写失败测试，再实现生成服务。
4. 先打通鬼畜榜、热梗、潜力视频的完整链路，再用同一契约扩展其他六页；全部验证后才称九页完成。
5. 修改 SSR 初始化和 hydration，覆盖日夜主题、懒加载、公开列表与个人数据边界。运行相关现有测试及生产构建。
6. 使用独立测试 Compose 与合成公开样本进行 HTTP 检查：九页正文不同；关闭 JS 可见主要内容；GET/HEAD/304、UTF-8、规范跳转、未知路径 404、内部路径拒绝正确。不得连接生产数据库。
7. 在真实浏览器验证直接访问、刷新、链接新开、前进后退、移动抽屉、主题、登录/收藏和多尺寸布局，保留截图及结果。账户测试使用 mock 或隔离环境。
8. 检查最终 diff 与发布说明，提交代码。推送、创建 PR、合并及生产部署遵从届时授权；本设计提交不包含部署。

验收标准：九个 URL 在无需登录、无需 JS 的 HTTP 响应中包含各自公开正文和真实链接；公开内容变更后两个轮询周期内完成发布；数据失败不覆盖成功页面或虚增时间；浏览器交互保持；未知网址不是首页软 404；无私密数据进入任何 HTML、启动 JSON、缓存或日志。

## 6. 部署与回滚边界

后续部署前重新核对真实生产 HEAD、Compose、镜像、路由和服务健康，确认已有业务备份可用以及旧 API/前端镜像可恢复；本次不基于历史记录假定当前部署。只新增公开页面服务及其专用缓存卷，并对 API/前端进行必要的定向更新。不修改生产环境变量文件、业务数据卷、SQLite、Cookie 或其他服务；不执行 `docker compose down -v`。

回滚恢复旧 API/前端镜像与旧 Nginx 配置，停用新增页面服务，保留其专用缓存卷。不需要业务数据库迁移。发布后再从公网核对正文、资源、图标和 HTTP 行为；本地通过不等于部署成功，也不等于 Bing 已收录。
