# GuichuHub Radar V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现已确认的六轴视频表现画像，使用真实观测、固定版本基线和真实近期增速，复用现有在线人数位置。

**Architecture:** Worker 持久化可信观测并构建不可变基线；API 批量读取榜单观测上下文和基线，纯函数计算雷达；React 负责显示分数、来源时间、缺失原因与可点按说明。观测更新和基线发布独立触发缓存失效，不改变榜单发现、排序或潜力算法。

**Tech Stack:** 现有 Python >=3.12、Flask、SQLAlchemy、Alembic、PostgreSQL、APScheduler、React 18、SVG、Vitest、pytest。无需新增产品依赖。

**Spec:** [已确认的维度设计](../../../雷达图-v2-维度设计.md)

本计划暂存于同一设计目录；实施开始后将设计与计划复制到隔离仓库的 docs/superpowers/specs 和 docs/superpowers/plans，作为同一提交内可评审的依据。

## Global Constraints

- 六轴顺序为播放规模、观众认可、收藏倾向、讨论活跃、分享倾向、近期增速；在线人数复用原卡片位置，不增加第二处展示。
- 不改排行榜排序、potential_score、trend_score 或原始历史计数，不迁移 Cookie/token/V2 数据，不部署。
- 增速目标 6 小时，合格实际间隔 5～7 小时；同比距离相同选择更早起点；真实零、缺失和计数下降分开。
- 比率为次/千播放；认可与讨论分别由两个子指标分位分等权平均，明确复合分含义。
- 互动最低播放 1,500；每个参考指标至少 200 个去重视频；周一北京时间 00:00 更新，版本内固定，首启允许启动基线。
- 累计观测有效期 24 小时；近期增速末点与在线人数有效期 90 分钟；可用性取决于实际时间和来源。
- 估算、未知来源、参考不足或无区分度时不伪造分数；每条视频用同一完整观测计算累计轴。
- 新增数据库迁移只在测试新建的 PostgreSQL 中执行；生产迁移和发布属于后续独立步骤。

## Review Focus

- 旧观测没有实测来源证明：保持未知，不自动当成实测；冷启动不把当前数据倒填到历史截止时间。
- 观测数据变化而抓取缓存版本不变：最新雷达和在线人数仍需更新；缓存跨过有效期或基线到期也不能继续显示可用。
- 基线少于 200、全同值、含 NaN/Infinity、年龄跨组：固定合并规则、明确不足状态、无未来样本。
- 在线数为 0/1/近似数或最新行在线采集失败：保留原始精度，选择最后有效在线观测并注明它自己的时间。
- 单轴缺失、两轴连续缺失和手机触控：断线不填充，真实零在中心；说明可点按且可由键盘访问。

### Task 2: 纯计算引擎与明确状态

**Files:** Create backend/utils/radar_v2.py、backend/tests/test_radar_v2.py；Modify backend/utils/radar_metrics.py 保留 v1 兼容入口。

**Interfaces:**
- build_baseline(contexts: list[dict], cutoff_ts: int, valid_until: int) -> dict，含算法 radar-v2、版本、截止/到期、各指标排序参考值、样本量与固定年龄合并映射。
- build_video_radar(context: dict, baseline: dict | None, now: int) -> dict，顶层含 algorithm_version、baseline_version、observed_at；轴 id 为 reach、approval、retention、discussion、sharing、growth。
- 每轴返回 label、score、raw、unit、status、reason、reference、components；components 记录复合轴原始子指标及分位分。
- status 取 available / unavailable / stale / low_sample / insufficient_baseline / invalid；reason 区分观测不足、计数下降、基准无区分度、来源未知、缺字段和到期。
- 在线信息由 build_online_observation(context: dict, now: int) -> dict 返回 count、display、precision、observed_at、status，不进入雷达轴。

- [ ] 写失败测试：单指标参考 [1,2,2,4] 中 x=2 为 50 分；原始 0 为 0；同值同分；样本不足/全同值不给可用分；年龄边界 1/3/7/14/30 天按前闭后开，两个相邻候选组同距优先年轻。
- [ ] 增速测试：从 6 小时前 1,000 到现在 1,600 得 100/小时；5～7 小时用实际时间；4 小时/8 小时不足；下降为 invalid；相同播放为 0；末点未来、过期或估算不可用。
- [ ] 维度独立性测试：仅改变收藏/分享/评论对应独立轴变化；调整 trend_score、potential_score 不改变任何 v2 轴；超百万不会触发固定封顶；缺一个子指标不当 0 平均。
- [ ] 运行 pytest tests/test_radar_v2.py --no-cov，先确认失败，再实现纯计算；使用有限数校验和二分查找计算分位，不改 scorer.py。
