## 行为

九个地址：`/`、`/rankings/kichu`、`/memes`、`/rankings/potential`、
`/meme-materials`、`/bgm`、`/materials`、`/insights/discussion`、`/up-trends`。
直接访问即可获得栏目正文、一个 H1、自指 canonical 和原生导航链接。
React 从同一公开快照 hydration，之后恢复主题、身份、收藏和图表交互。
浏览器内切换同步 URL、title、canonical；前进后退和新窗口遵循浏览器行为。

内部 API 逐层筛选允许公开的持久数据；不触发采集，不读取 LIVE 临时缓存，
不依赖账户 Cookie。UP 分析单独读取、单独检测版本。
Node 每轮结束 60 秒后重试，读取超时 10 秒，单轮不会重叠。
只有内容变化才更换页面和内容确认时间。数据源、渲染或磁盘失败时保留成功内容。
含糊的历史空数组视为不可用，不能证明成功空榜，不覆盖已有正文。
显式标记的成功空态可由发布契约接收。

持久缓存使用专用 `public_pages_cache`，批次文件写完后原子切换 CURRENT。
业务数据、凭据、Cookie、既有卷不挂入此服务。新构建先用兼容数据重建页面，
不会直接返回引用旧资产的文档。Nginx 启动时核对客户端和页面服务 build_id，
每次页面代理请求也携带固定的期望构建 ID，不匹配时页面服务返回 503。
同构建的已提交缓存恢复不需要重新写盘；新构建重建提交失败则下轮重试。
HTML 支持 ETag、HEAD、304；未知地址 404，规范尾斜杠 308，
从未成功发布的栏目在源不可用时为 503、Retry-After: 60、noindex。

## 实施中的决定及限制

- 桌面品牌链接回到首页；原管理员五连击手势保留。交互变化是单击品牌会导航。
- 单元测试使用四个 worker，避免既有 lazy 测试在编译竞争下超时；代价仅是测试并行度。
- 大字段边界测试使用 ASCII，以独立验证字段截断；另一个中文样本专门验证总字节上限，避免混淆两种约束。
- 栏目与首页摘要作为一个发布批次切换；任一候选失败，两者保留旧版，其他栏目继续。代价是该批次延至下一轮重试。
- 持久看板没有雷达 API 衍生数据，雷达继续在浏览器取数后增强。初始 HTML 提供已持久的真实作品及公开统计，不伪造观测。
- 按批准计划保留缓存历史，不自动删除历史目录。应监控专用卷空间；每批有 64 MiB 上限，但历史总量会增长，制定保留策略需另行处理。
- 完整逐页 description、结构化数据、九页 sitemap 和 IndexNow 属于后续阶段。现有 sitemap 保留首页，真实导航可发现栏目；本次不声称 Bing 已收录。

## 后续生产发布与回滚

生产发布必须另行授权，并现场核对 HEAD、Compose、镜像、Caddy、网络及服务状态。
先确认最近备份可恢复，记录旧 API/前端镜像摘要和配置，构建同源的两个前端目标。
新增专用页面服务及缓存卷，定向更新 API/前端及必要入口配置，不修改环境变量文件，
不迁移业务数据，不触碰 SQLite、Cookie、敏感文件和无关服务。
不得执行 `docker compose down -v`。

上线后从公网验证九页正文、404/503、资产、图标、canonical 和内部入口拒绝。
回滚恢复旧 API/前端镜像及旧入口配置，停用新页面服务并保留其缓存卷；无需数据库迁移。
HTTP 成功不代表 Bing 已抓取或 AI 一定引用，搜索重新抓取和索引更新需要时间。
